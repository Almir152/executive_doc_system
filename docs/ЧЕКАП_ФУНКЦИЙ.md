# Полный чек-лист: что должно работать и как это проверить

Документ для ручной проверки приложения человеком, который не знает
технического задания. Каждый пункт — это точный маршрут: **куда нажать** и
**что должно появиться**. Если появилось не то или кнопки нет — это дефект,
запишите пункт и текст сообщения.

Проверяйте **по порядку** и **сначала только на Linux** — так быстрее находить
ошибки. На Windows идите только после того, как на Linux всё сошло. Пункты,
которые на Linux проверить нельзя, помечены `[только Windows]`.

## Обозначения

* `[Linux + Windows]` — можно и нужно проверить на обеих системах.
* `[только Windows]` — проверяется только на Windows (сборка, шрифты, печать,
  системное открытие файлов).
* `[только для ключа GigaChat]` — требует ключа, выданного Сбером. Без ключа
  шаг пропускается, но приложение обязано честно сообщить, что ключа нет.

## Главное правило навигации (прочтите перед стартом)

Главное окно — это **только список проектов и общие разделы слева**. Почти вся
работа с документами идёт в **отдельном рабочем окне проекта**:

> `Проекты` -> выберите строку проекта -> **«Открыть рабочее окно проекта»**
> (или двойной щелчок по строке).

Если рабочее окно не открыто, кнопок «+ Раздел», «+ Документ», «Печать формы»,
«+ Материал», «+ Связь с файлом архива», «Сформировать комплект» на экране нет
— это нормально, они живут внутри рабочего окна проекта.

# 0. Как запустить

## 0.1 Linux — запуск из исходников `[Linux]`

1. Откройте терминал в папке с проектом.
2. Если окружение ещё не готово, выполните один раз:

   ```bash
   python3 -m venv venv
   venv/bin/pip install -r requirements.txt
   ```

3. Чтобы **не испортить рабочие данные**, запустите проверку на отдельной
   пустой папке (приложение поймёт это по переменной окружения):

   ```bash
   EXECUTIVE_DOC_DATA_DIR=/tmp/eds_accept venv/bin/python main.py
   ```

   Для обычного запуска (с рабочими данными) — просто:

   ```bash
   venv/bin/python main.py
   ```

**Что должно появиться:** окно с заголовком `Единая система управления ИД`,
слева — список разделов, справа — заголовок `Рабочая область: Проекты`.

**Первый запуск на пустой папке.** Может один раз появиться окно
«Обновление программы» — это нормально, нажмите OK. Оно создаётся при
первичной подготовке базы и больше не покажется.

**Дефект:** окно не открылось; появилось окно с ошибкой; приложение закрылось
само без сообщения.

## 0.2 Windows `[только Windows]`

1. Соберите приложение: запустите `build_windows.bat` (появится папка `dist`).
2. Запустите `dist\ExecutiveDocSystem\ExecutiveDocSystem.exe` на компьютере
   **без установленного Python**.

**Дефект:** программа не запускается без Python; не хватает DLL.

## 0.3 Проверка журнала `[Linux + Windows]`

После запуска откройте файл журнала рядом с базой:
`storage/app.log` (или `/tmp/eds_accept/app.log` при запуске из п. 0.1).

**Ожидается:** строк с уровнем `ERROR` и текстом трассировки (Traceback) нет.
Одна строка про «проверочную запись» из старых тестов — не считается.

# 1. Проекты

## 1.1 Создание проекта `[Linux + Windows]`

Маршрут: `Проекты` -> кнопка **«+ Создать проект»**.

**Что должно появиться:** диалог «Новый проект» с полями «Наименование\*»,
«Направление\*» (выбор из списка), «Адрес».

1. Заполните Наименование и выберите Направление, нажмите OK.
2. **Ожидается:** проект появился в таблице (колонки ID, Направление,
   Наименование, Адрес).

## 1.2 Обязательные поля `[Linux + Windows]`

1. Откройте «+ Создать проект», оставьте Наименование пустым -> OK.
   **Ожидается:** предупреждение «Укажите наименование проекта», проект не
   создан.
2. Наименование заполните, а Направление не выбирайте -> OK.
   **Ожидается:** предупреждение «Выберите направление работ», проект не создан.

> Это тот самый дефект приёмки: раньше направление считалось не выбранным,
> даже когда оно выбрано. Теперь выбор направления работает.

## 1.3 Адрес необязателен `[Linux + Windows]`

1. Создайте проект с пустым Адресом.
2. **Ожидается:** проект создан, в таблице адрес пустой, нигде не написано
   «Не указан».

## 1.4 Открытие рабочего окна проекта `[Linux + Windows]`

1. Щёлкните по строке проекта (она подсветится).
2. Нажмите **«Открыть рабочее окно проекта»**.
   **Ожидается:** открывается **отдельное окно** с заголовком «Рабочее окно
   проекта», вверху название проекта, ниже кнопки и таблицы.
3. Закройте это окно. Теперь **дважды щёлкните** по строке проекта.
   **Ожидается:** снова открывается отдельное окно.
4. Откройте окно ещё раз, не закрывая предыдущее.
   **Ожидается:** старое окно закрылось, открылось новое, ошибок нет.
5. Не выбирая проект, нажмите кнопку.
   **Ожидается:** предупреждение «Сначала выберите проект в таблице».
6. Потяните за угол окна и уменьшите его, затем прокрутите содержимое.
   **Ожидается:** окно свободно уменьшается и увеличивается, справа/снизу
   появляется ползунок прокрутки, ничего не обрезается.

> Это второй исправленный дефект: раньше окно создавалось как «вложенная
> панель» и его не было видно, а само окно не уменьшалось и не
> прокручивалось.

## 1.5 Удаление проекта `[Linux + Windows]`

1. Выберите проект без документов и архива -> **«Удалить проект»**.
   **Ожидается:** вопрос с подтверждением, после «Да» проект исчезает.
2. Проверьте проект, в котором есть выпущенный документ или архивный файл:
   **Ожидается:** удаление запрещено с текстом причины.

# 2. Справочники

Маршрут: слева `Справочники`. Четыре вкладки: «Организации»,
«Представители», «Виды разделов», «Типы материалов».

## 2.1 Виды разделов и Типы материалов `[Linux + Windows]`

**Ожидается:** вкладки «Виды разделов» и «Типы материалов» заполнены заранее
(АС, АП, ВК, КЖ и т. п.). Это не ошибка и не требует ручного ввода.

## 2.2 Организации `[Linux + Windows]`

1. Вкладка «Организации» -> **«+ Добавить»**.
2. Заполните «Краткое наименование\*», при желании ИНН/ОГРН/адрес -> OK.
   **Ожидается:** запись появилась в таблице.
3. Выберите строку -> **«Изменить»**, поменяйте наименование -> OK.
   **Ожидается:** изменилась та же строка, второй записи не появилось.
4. Выберите строку -> **«Удалить»** -> «Да».
   **Ожидается:** неиспользуемая организация удаляется.

## 2.3 Поиск + правка при включённом поиске `[Linux + Windows]`

1. Заведите три организации: «Альфа», «Монтаж», «Строй».
2. В поле поиска введите `монтаж`.
   **Ожидается:** в таблице осталась одна строка — «Монтаж».
3. Не очищая поиск, выберите строку -> **«Изменить»**, поменяйте наименование.
   **Ожидается:** изменилась именно «Монтаж», а не первая организация списка.

> Это третий исправленный дефект: раньше при поиске правилась чужая запись.

## 2.4 Представители `[Linux + Windows]`

1. Вкладка «Представители» -> **«+ Добавить»**, выберите организацию, должность
   и ФИО -> OK. **Ожидается:** запись появилась.
2. Попробуйте удалить организацию, у которой есть представитель.
   **Ожидается:** удаление запрещено с объяснением.

## 2.5 Нормативы `[Linux + Windows]`

Маршрут: слева `Нормативы`.

1. Введите в поиск `СП` или `ГОСТ`.
   **Ожидается:** таблица (Шифр, Наименование, Категория) фильтруется.
   Список небольшой и встроенный — это норма, а не пустой экран.

## 2.6 Формы документов `[Linux + Windows]`

Маршрут: слева `Формы документов`.

1. **Ожидается:** таблица (Тип документа, Версия, Наименование формы,
   Основание, Разделов). У АОСР должны быть две версии: полная (рекомендуемый
   образец) и краткая, актуальная помечена.
2. Щёлкните **в любом месте строки** формы (не обязательно по номеру слева).
   **Ожидается:** ниже появляется список разделов этой формы (нумерация и
   количество блоков).

> Исправлено: раньше состав формы появлялся только по щелчку в узкий номер
> строки слева; теперь строка выделяется целиком из любой ячейки.

# 3. Карточка проекта и разделы (в рабочем окне)

Откройте рабочее окно проекта (п. 1.4).

## 3.1 Карточка `[Linux + Windows]`

1. **«Редактировать карточку»** -> выберите заказчика, генподрядчика и
   необходимые организации -> OK.
   **Ожидается:** данные сохранились и видны в карточке проекта.

## 3.2 Разделы проекта `[Linux + Windows]`

1. **«+ Раздел»** -> выберите вид раздела, задайте код и наименование -> OK.
   **Ожидается:** раздел появился в таблице «Проектная документация».

# 4. Документы и формы

## 4.1 Создание документа `[Linux + Windows]`

1. В рабочем окне в блоке «Документы проекта» -> **«+ Документ»**.
2. Выберите «Вид документа» (АОСР/АООК/АОУСИТО/Акт испытаний), при
   необходимости поменяйте дату -> OK.
   **Ожидается:** документ появился в дереве; номер система присвоила сама
   (вручную номер не вводится).

> Вид документа важен для связей: материал связывается только с **Актом
> испытаний** (п. 5.2), а завершать **АОСР** может только итоговый
> акт АООК/АОУСИТО (п. 5.4). Поэтому для полной проверки создайте все виды.

## 4.2 Выпуск без заполнения `[Linux + Windows]`

1. Выберите документ в дереве -> **«Выпустить документ»**.
   **Ожидается:** выпуск не произошёл, показан список незаполненных
   обязательных полей.

## 4.3 Работа с формой `[Linux + Windows]`

1. Выберите документ -> **«Открыть форму (п.65)»**.
   **Ожидается:** форма открылась (в рабочей области или отдельным окном — см.
   п. 4.6), поля построены по нормативной форме.
2. Заполните обязательные поля -> **«Проверить заполнение»**.
   **Ожидается:** либо «всё заполнено», либо список замечаний.
3. **«Сохранить форму»**.
   **Ожидается:** черновик сохранён.

## 4.4 Выпуск и версии `[Linux + Windows]`

1. Заполните форму полностью -> **«Сохранить форму»** ->
   **«Выпустить документ»**.
   **Ожидается:** диалог «Выпуск документа» с полем даты; укажите дату и
   подтвердите. Документ получает статус «выпущен».
2. Пустая дата -> выпуск невозможен, есть объяснение «Укажите дату».
3. **«Новая редакция»** для выпущенного документа.
   **Ожидается:** создаётся следующая версия (в дереве видно номер версии).

## 4.5 Печать формы `[Linux + Windows]`

1. Выберите документ -> **«Печать формы»** -> выберите, куда сохранить PDF.
   **Ожидается:** PDF создан и открылся в просмотрщике (Windows) или
   сохранён и открыт (Linux), в «Истории» появилась запись.

## 4.6 Режим открытия формы и разворот `[Linux + Windows]`

1. В рабочем окне найдите «Открывать форму:» и переключите на «Отдельно».
   Откройте форму. **Ожидается:** форма открылась отдельным окном.
2. Верните «В правой рабочей области» и откройте форму.
3. Нажмите **«Развернуть форму»** и снова.
   **Ожидается:** форма разворачивается и возвращается, окно не ломается,
   поля прокручиваются, окно можно уменьшить и увеличить.

## 4.7 Закрытие формы без сохранения `[Linux + Windows]`

1. Откройте форму, измените поле и закройте окно/форму без сохранения.
   **Ожидается:** вопрос «Сохранить черновик перед закрытием?» с вариантами
   Сохранить / Не сохранять / Отмена.

# 5. Материалы и связи

## 5.1 Материал `[Linux + Windows]`

1. В рабочем окне блок «Материалы» -> **«+ Материал»**.
2. Выберите тип, задайте наименование, количество, сроки -> OK.
   **Ожидается:** материал появился в таблице; при необходимости показывается
   подсказка о документе качества/сроках.

## 5.2 Связь материала с актами `[Linux + Windows]`

**Предварительно:** в дереве документов должен быть документ вида
**«Акт испытаний»** (создайте в п. 4.1, выбрав этот вид). С АОСР материал не
связывается — это разные виды документов.

> Если акта испытаний в проекте нет, окно честно пишет «В проекте нет актов
> испытаний. Создайте акт испытаний (ТЗ п.36)». Это правильное поведение, а не
> дефект.

1. Выберите строку материала -> **«+ Акты испытаний материала»** -> отметьте
   акт(ы) -> OK.
   **Ожидается:** акты появились в таблице «Акт испытаний / Дата».
2. Выберите материал, затем акт -> **«Убрать связь с актом»**.
   **Ожидается:** связь убрана.

## 5.3 Связь документа с файлом архива `[Linux + Windows]`

Сначала загрузите файл (раздел 6), потом:

1. Выберите документ в дереве -> **«+ Связь с файлом архива»** -> выберите
   файл и роль -> OK.
   **Ожидается:** связь появилась в таблице «Файл / Категория / Роль / Версия».
2. Выберите связь -> **«Удалить связь»**.
   **Ожидается:** связь убрана, файл в архиве остался.

## 5.4 Акты, которые завершает документ `[Linux + Windows]`

**Предварительно:** создайте в дереве два документа (п. 4.1) — **АОСР** и
любой итоговый (**АООК** или **АОУСИТО**). Итоговый акт завершает только
акты скрытых работ, поэтому связка «АООК завершает АОСР» — правильная.

> Если АОСР в проекте нет (или все уже связаны либо это выбран сам АОСР), окно
> честно пишет «В проекте нет свободных актов освидетельствования скрытых
> работ». Это правильное поведение, а не дефект.

1. Выберите в дереве **итоговый** документ (АООК/АОУСИТО), не АОСР ->
   **«+ Акты, которые завершает документ»** -> отметьте АОСР.
   **Ожидается:** акт появился в таблице «АОСР / Период работ / Проверка дат».
2. **«Убрать связь актов»** — связь убирается.
3. Заполните АОСР периодом работ из двух дат (п. 4.3) и проверьте, что колонка
   «Проверка дат» не выдаёт противоречий, если итоговый акт позже АОСР.

# 6. Архив файлов

Маршрут: слева `Архив файлов (SHA-256)`.

## 6.1 Загрузка файла `[Linux + Windows]`

1. **Важно:** сначала выберите проект в разделе `Проекты`.
2. Вернитесь в `Архив файлов (SHA-256)`, выберите «Категория» ->
   **«Добавить файл в архив»** -> выберите файл на диске -> заполните детали
   (вид документа качества, сроки, номер) -> OK.
   **Ожидается:** строка появилась в таблице (ID, Категория, Имя файла, Вид
   качества, Срок действия, Связей).

## 6.2 Дедупликация `[Linux + Windows]`

1. Загрузите тот же самый файл второй раз.
   **Ожидается:** сообщение «Дубликат», вторая физическая копия не создаётся.

## 6.3 Поиск `[Linux + Windows]`

1. Введите в поиск часть имени файла.
   **Ожидается:** таблица отфильтрована.

## 6.4 Смена проекта `[Linux + Windows]`

1. Выберите в `Проекты` другой проект, вернитесь в архив.
   **Ожидается:** таблица архива показывает файлы **нового** проекта, а не
   прежнего.

## 6.5 Удаление из архива `[Linux + Windows]`

1. Выберите неиспользуемый файл -> **«Удалить из архива»** -> «Да».
   **Ожидается:** файл удалён.
2. Попробуйте удалить файл, связанный с документом.
   **Ожидается:** запрет с объяснением, что сначала нужно снять связи.

# 7. Комплекты и печать состава

## 7.1 Формирование комплекта `[Linux + Windows]`

1. В рабочем окне блок «Комплекты проекта» -> **«Сформировать комплект»**.
   **Ожидается:** диалог «Формирование комплекта»: список документов с
   галочками, кнопки «Отметить все»/«Снять все», выбор типа выгрузки,
   название корневой папки, кнопка «Выбрать папку».
2. Снимите галочку у одного документа, чтобы намеренно получить замечание.
3. Нажмите сформировать.
   **Ожидается:** список замечаний и вопрос «Всё равно завершить?».
4. Завершите.
   **Ожидается:** папка создана, в ней PDF документов, `РЕЕСТР ВЫГРУЗКИ.pdf` и,

# 11. Только Windows

Эти пункты на Linux пройти невозможно.

1. **Сборка и запуск без Python** — `build_windows.bat`, запуск `.exe` на
   чистой машине.
2. **Хранение ключа DPAPI** — ключ должен лежать в защищённом хранилище
   Windows, а не открытым текстом.
3. **Открытие PDF и папок** системной программой (`os.startfile`) — PDF
   открывается, папка комплекта открывается в Проводнике.
4. **Шрифт Times New Roman** — проверьте свойства PDF: шрифт Times New Roman,
   размер 11 pt, заполняемый текст курсивом; поля A4: верх 20 мм, лево 10 мм,
   право 10 мм, низ 10 мм.
5. **Печать на бумаге** — реальный принтер, поля и количество страниц.
6. **Обновление со старой схемы** — запуск новой сборки на базе прошлой версии
   (до миграций автоматически создаётся копия, данные сохраняются).

# 12. Что НЕ является дефектом

* Пустые вкладки «Организации» и «Представители» — их заполняет оператор.
* Раздел «Нормативы» содержит небольшой встроенный список — так задумано.
* «Интернет-ИИ» без ключа сообщает `not_configured` и молчит — так задумано.
* Один раз при первом запуске на пустой папке появляется окно «Обновление
  программы».
* Если рабочее окно проекта не открыто, кнопок документов нет — это порядок
  работы, а не пропавшие кнопки.
* «В проекте нет актов испытаний» (п. 5.2) — значит, в дереве нет документа
  вида «Акт испытаний»; создайте его.
* «В проекте нет свободных актов освидетельствования скрытых работ» (п. 5.4) —
  значит, нет свободного АОСР или выбран сам АОСР; это защита, а не ошибка.

# 13. Что считать дефектом

* Любое расхождение с колонкой «Ожидается».
* Данные пропали или изменились без действия оператора — самое серьёзное.
* Программа падает или закрывается без сообщения.
* Ожидаемая кнопка отсутствует там, где написано.
* Пути к диску и имена папок видны там, где их быть не должно.
