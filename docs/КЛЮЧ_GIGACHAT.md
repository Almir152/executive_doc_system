# Как включить интернет-ИИ GigaChat

Ключ авторизации вводите **сами, в поле приложения**. Никому, в том числе
разработчику, ключ пересылать не нужно: он не обращается к нему при проверке
работы программы, и в переписке ключ раскрывается.

## 1. Получите ключ

1. Откройте личный кабинет GigaChat Сбера и войдите под своей учётной записью
   (личной или организации — от этого зависит область доступа).
2. В разделе с API создайте ключ авторизации и скопируйте его. Ключ выдаётся
   один раз и сохраняется только у вас.
3. Запомните область доступа, указанную при создании ключа:
   - физическое лицо — `GIGACHAT_API_PERS`;
   - организация — `GIGACHAT_API_CORP`.

## 2. Введите ключ в приложении

1. Запустите приложение и откройте **«Настройки» → «Параметры ИИ»**.
2. В поле **«Ключ GigaChat»** вставьте ключ.
3. Проверьте остальные значения:
   - **адрес сервиса**: `https://api.giga.chat/v1`;
   - **модель**: `GigaChat-Max` (подставьте модель, доступную вашему ключу);
   - **область доступа (scope)**: та же, что при выдаче ключа.
4. Нажмите **«Сохранить параметры ИИ»**, затем **«Проверить подключение»**.

Ожидаемый результат проверки:

- поле ключа очищается — оно хранит значение только до передачи настроек;
- строка **«Хранение ключа»** сообщает, что ключ зашифрован средствами Windows
  («Ключ сохранён: защищённое хранилище Windows (DPAPI)»); на Linux будет
  предупреждение, что ключ сохранён открытым;
- появляется ответ модели, например «1. Проверить срок испытаний…».

## 3. Включите интернет-режим

**«Настройки» → «Режим работы» → «Интернет-ИИ»**, затем
**«Сохранить параметры ИИ»**. Выбранный режим сохраняется и после закрытия
программы.

Проверьте его работу на проекте: **«ИИ» → «Предложить»**. Придут черновики
предложений, которые нужно принять или отклонить — программа ничего не
подписывает и не выпускает сама.

> Приложение **не отправляет наружу** тексты архивных файлов, имена файлов и
> содержимое PDF. В интернет-режиме передаются только сведения о составе
> проекта и ваш запрос.

## 4. Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| «не задана модель или ключ авторизации» | Ключ не вставлен или не нажата кнопка сохранения |
| «Ключ авторизации отклонён (код 401)» | Ключ выдан для другой области доступа или отозван — выпустите новый и проверьте область доступа |
| «Не удалось обратиться к GigaChat» | Нет сети или требуется прокси: задайте `HTTPS_PROXY=http://прокси:8080` и повторите |
| «Не удалось обратиться к GigaChat: … CERTIFICATE_VERIFY_FAILED …» | Сеть перехватывает TLS — см. раздел 5 |
| «Сервис не вернул ответ» | Попробуйте другую модель из списка доступных вам |
| Проверка прошла, но ответ не появляется | Проверьте, что выбран именно интернет-режим ИИ, а не локальный |

## 5. Если сеть перехватывает шифрование (CERTIFICATE_VERIFY_FAILED)

Ошибка вида

```text
[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed:
self-signed certificate in certificate chain
```

означает, что соединение проходит не напрямую, а через корпоративный прокси
или антивирус, который подменяет сертификат своим. Приложение специально не
отключает проверку сертификатов: по этому соединению передаётся ключ
авторизации, и доверять неизвестному посреднику нельзя.

Нужно указать корневой сертификат вашей сети в отдельном файле `.pem`:

1. Возьмите корневой сертификат у службы ИТ (файл `.crt` или `.pem`), либо
   экспортируйте его из хранилища системы.
2. Если файл в формате DER (`.crt`/`.cer`), переведите его в `.pem`:
   ```bash
   openssl x509 -inform DER -in corporate.crt -out corporate.pem
   ```
3. Запустите приложение с переменной окружения:
   ```bash
   export EXECUTIVE_DOC_CA_BUNDLE="$PWD/corporate.pem"
   python main.py
   ```
   Под Windows — «Свойства» системы → «Дополнительно» → «Переменные среды»,
   новая переменная `EXECUTIVE_DOC_CA_BUNDLE` со значением
   `C:\путь\к\corporate.pem`.
4. Нажмите **«Проверить подключение»** снова.

Альтернатива — стандартная переменная `SSL_CERT_FILE`, если она уже настроена
в вашей организации.

Файл сертификата нужен один раз: он не попадает в базу приложения и не
передаётся в GigaChat. Ошибки «Файл сертификатов не найден» и «Не удалось
прочитать сертификаты» означают, что путь указан неверно.

## 6. Если ключ сохранён открытым

На Linux и при отсутствии DPAPI ключ лежит в `storage/settings.json` в открытом
виде. Чтобы этого избежать, задайте переменную окружения и удалите ключ из
настроек:

```bash
export EXECUTIVE_DOC_GIGACHAT_KEY='ваш-ключ'
```

Затем в приложении: **«Забыть ключ»**. При следующем запуске приложение
попробует перенести значение в защищённое хранилище автоматически.

## 7. Отзыв ключа

Ключ отзывается в личном кабинете GigaChat. После отзыва приложение
покажет ошибку «Ключ авторизации отклонён (код 401)»: введите новый ключ по
шагу 2.
